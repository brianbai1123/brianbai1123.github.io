# 全站字体与三主题同步设计

## 目标

把首页已经用于七个习惯站的字体、宣纸/青瓷/夜读三主题和单向主题传递，扩展到其余七个独立站点：

| 站点 | 路径 | 仓库 | 本地存储键 |
| --- | --- | --- | --- |
| 原则 | `/ruiprincipal/` | `brianbai1123/ruiprincipal` | `ruiprincipal:theme` |
| 进化心理学 | `/ep/` | `brianbai1123/ep` | `ep:theme` |
| 孙子兵法 | `/sunzi/` | `brianbai1123/sunzi` | `sunzi:theme` |
| 周易 | `/zhouyi-reading-cards/` | `brianbai1123/zhouyi-reading-cards` | `zhouyi-reading-cards:theme` |
| 历久 | `/lijiu/` | `brianbai1123/lijiu` | `lijiu:theme` |
| 菜根谭 | `/cgt/` | `brianbai1123/cgt` | `cgt:theme` |
| 三十六计 | `/36/` | `brianbai1123/36` | `36:theme` |

加上已经完成的 `/7habit/`，首页一共向八个子站传递主题。

## 采用方案

每个仓库原生实现同一份主题协议，不引入远程公共脚本或共享 npm 包。

各站技术结构不同：原则、进化心理学、历久、菜根谭和三十六计是 Next.js；孙子兵法和周易是静态 HTML/CSS/JavaScript。原生实现能保留各自构建与部署方式，避免一个远程资源故障同时影响全部站点。

主题协议保持一致，但实现只共享行为和视觉值，不强求共享源码。

## 首页链接同步

首页把当前仅识别 `/7habit/` 的链接处理扩展为八个受支持路径：

- `/7habit/`
- `/ruiprincipal/`
- `/ep/`
- `/sunzi/`
- `/zhouyi-reading-cards/`
- `/lijiu/`
- `/cgt/`
- `/36/`

对于同源且属于上述路径的链接，首页写入当前主题：

```text
?theme=paper
?theme=celadon
?theme=night
```

处理规则：

1. 保留链接原有查询参数。
2. 保留锚点；孙子、周易和历久依赖锚点导航。
3. 已有 `theme` 参数时覆盖为首页当前主题。
4. 不改写外域链接和未列入协议的本站路径。
5. 普通链接、弹窗 iframe 和弹窗“新页面打开”共用改写后的地址。
6. 动态插入的链接继续由现有 MutationObserver 处理。

主题只从首页向子站传递。子站内切换主题不修改 `principles:theme`。

## 子站主题状态

每个子站使用自己的存储键，互不共享。解析顺序统一为：

1. URL 中合法的 `theme` 参数；
2. 本站 localStorage 中合法的主题；
3. 默认主题 `paper`。

合法 URL 参数会写入本站存储，因此从首页进入后刷新仍保持该主题。非法参数被忽略，不覆盖有效存储值。localStorage 被禁用或抛出异常时，页面仍应用合法 URL 参数或默认主题。

主题切换器只更新当前站的 `<html data-theme>` 和本站存储键，不更新 URL，也不写首页或其他子站的键。

为避免首屏闪烁，主题解析在页面主体绘制前执行：

- Next.js 站在根 layout 的 `<head>` 中放置内联首屏脚本，并对根元素启用 hydration 差异抑制。
- 静态站在文档 `<head>` 中、主题 CSS 生效前后尽早执行等价脚本。

## 字体与视觉

七个站统一采用首页现有字体角色：

- 正文和界面：Noto Sans SC，字重 400/600/700；
- 标题：Noto Serif SC，字重 600/700/900；
- 数字和拉丁展示：Cormorant Garamond，字重 500/600，含 italic；
- 引语、导读或适合手写语气的文字：LXGW WenKai Screen。

主题变量逐值复用首页的宣纸、青瓷和夜读配色。主题切换器复用首页的名称、双色斜切圆形色样、选中状态和 `radiogroup`/`radio` 可访问性语义。

各站保留现有布局、内容层级和交互结构。允许为适配现有页面选择合适的切换器位置，但不借此重做页面。

历久现有的浅色/深色模式被三主题完整替换，不保留第四种兼容模式。若旧存储值不是 `paper`、`celadon` 或 `night`，按无效值处理并回退到宣纸。

## 技术边界

- 不改变各站内容。
- 不建立跨站双向存储同步。
- 不让一个子站的主题选择自动影响另一个子站。
- 不增加服务端状态、cookie 或跨域通信。
- 不把主题参数自动附加到站内每一个链接；站内页面依靠本站存储保持主题。
- 不统一各站布局，只统一字体角色、主题色和切换控件。

## 测试与验收

### 单元与源码契约

首页测试覆盖：

- 八个受支持路径均被改写；
- 原查询参数与锚点保留；
- 不相关路径和外域链接不变；
- storage 不可用时，主题变更事件仍能驱动动态链接更新。

每个子站测试覆盖：

- URL、存储和默认值的解析优先级；
- 非法 URL 参数不污染存储；
- 主题键与首页及其他站隔离；
- 首屏脚本在 hydration 或应用代码之前运行；
- 三主题、字体和切换器契约存在。

静态站使用现有测试体系；若没有合适测试入口，增加最小 Node 测试以验证主题解析函数和 HTML/CSS 契约。

### 构建与浏览器验证

每个仓库运行其完整测试、lint、类型检查和生产构建；没有某项脚本时记录为不适用，不虚构结果。

浏览器集成验证覆盖：

1. 首页三种主题分别进入八个子站；
2. 普通链接、弹窗 iframe 和“新页面打开”；
3. 孙子、周易和历久的锚点未丢失；
4. 子站切换不改变首页存储；
5. 各子站直接访问和刷新保留本站上次主题；
6. 非法主题参数正确回退；
7. 桌面端与移动端的三主题外观；
8. 页面无新增 console error、page error 或 hydration 警告。

## 发布顺序

先分别发布七个子站，确认线上资源可访问；最后发布首页的八站链接改写。这样不会出现首页先发出主题参数、子站却尚未识别的中间状态。
